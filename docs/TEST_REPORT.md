## 正常系

同じ職員をフロアと統括に同時加算しないこと、短A終了01:00以降は人数から外れること、入力順を変えても配置結果が変わらないことも確認。
性別の値を追加しても判定が変化しないことを確認しました。

同じ72人＋架空職員（合計122人）で監査期間を2026年10月の1か月分（31日・5,952配置枠）に広げた例でも、重大NG0・人数不足0・要確認5件と、7日間の正常基準と同じ結果になることを確認しました。
この例は月をまたぐ規模でも監査ロジックが崩れないことの確認が目的で、月間残業上限（`OT_MONTH`）・月間時間枠（`MONTH_PLAN_FRAME`）が実際に発報する境界までは作り込んでいません。それらのコード自体は上記の意図的NG11・13番で個別に検証済みです。

## 6か月の手薄な例（2026-09-26 追加）

原本の72人だけを使い、人が足りない枠が出ても増員しない設定で、2026年10月〜2027年3月の6か月分を作成しました(`data/understaffed_*`、`tests/build_understaffed_series.py`)。
月ごとの重大NG件数は10月1,764件・11月3,270件・12月3,303件・1月3,366件・2月3,018件・3月3,292件で、全枠に対する不足率は10月27.7%、11月以降は53〜54%で推移します。
年休は全員「付与10日・基準日2026-04-01」で固定し、まだ5日取得できていない人の残り日数を6か月に均等に振り分けています。10月〜1月は要確認(`LEAVE_PENDING`)が残りますが、2月には全員が5日の取得を終える計算です。
これらの数値は既知の生成結果として`tests/test_audit.py`に固定し、生成ロジックを変えた際に意図した変化か気づけるようにしています。

## 監査ツールの汎用性（2026-09-26 追加）

「統括」という役割名・「統」という勤務コード、「休・明・有」の3コード、週の起算曜日は、これまでengine.py内に固定で書かれていましたが、config.jsonの`supervisor_role`・`supervisor_shift_code`・`off_code`・`post_night_code`・`paid_leave_code`・`week_start_weekday`で施設ごとに変更できるようにしました。
指定がない場合は元の値のまま動くため、既存のデータ・テストの結果は一切変わりません。実際にこれらを別の名前・コードに変えても、判定結果(重大NG・要確認の件数)がまったく変わらないことをテストで確認しています。
